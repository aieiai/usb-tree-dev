# Rot\-Gen 协议规范

# 背景

设备之间的通信通常横跨 UART、RS\-485、CAN、TCP、UDP、进程间队列等多种介质。若每个产品都自行定义帧头、长度、校验方式、序号和错误处理，会带来以下问题：

- 相同业务能力难以在不同硬件平台和传输介质之间复用；

- 设备只收到半个包、包内出现帧头或线路受干扰时，接收端容易失去同步；

- 命令、响应、通知、广播和分片各自实现，状态机难以统一；

- 协议升级时缺少版本边界，新旧设备可能错误解析对方数据；

- 问题定位依赖临时日志，缺少统一的丢包、校验错误和超时观测点。

ROT 是位于应用协议与传输介质之间的一层轻量级通用数据帧规范。它提供稳定的二进制“信封”，使业务代码只关注命令和业务数据，而帧同步、长度、完整性校验、寻址和传输适配由统一机制处理。

ROT 不是完整的网络协议栈，也不替代具体业务协议。其作用是规定一帧数据如何组织、校验、发送、接收和解释，使不同模块在明确约定下可以互通。

# 帧结构总览

```Markdown
┌──────────────────────────┐
|     rot-gen protocol     |
├────────────┬─────────────┤
│   Header   │   Payload   │
│    10B**    ** │     nB      │
└────────────┴─────────────┘
```



### Header帧结构

|**偏移**|**字段名**|**长度**|**说明**|
|---|---|---|---|
|0|`sof`|1B|起始字节，`'R': 0x52`|
|1|`version`|1B|协议版本|
|2|`options`|1B|控制可选项|
|3|`src_addr`|1B|源地址|
|4|`dst_addr`|1B|目的地址|
|5|`payload_length`|2B|Payload 字节数|
|7|`secret_key`|2B|保留|
|9|`header_crc8`|1B|Header CRC8|
|10|`package_crc16`|2B|整包 CRC16|



### Options 位定义

`options` 字段为 8 位控制标志，定义如下：

|**Bit**|**名称**|**值**|**说明**|
|---|---|---|---|
|0|`OPT_ENCRYPT`|0x01|0 \- 明文, 1 \- 密文|
|1|`OPT_FRAGMENT`|0x02|0 \- 完整, 1 \- 分片|
|2|`OPT_BROADCAST`|0x04|0 \- 专项, 1 \- 广播|
|3|`OPT_REQUEST`|0x08|0 \- 响应, 1 \- 请求/通知|
|4\-7|`OPT_RESERVED`|||
|||||

|---|---|---|
